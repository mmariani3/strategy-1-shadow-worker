# Proposed automated-review acceptance method

**Proposal only; not an amendment to a governing master and not permission to activate reviews.**

Purpose: remove routine dependence on the user's live availability while preserving Strategy #1 v0.3 and Experiment Plan v0.5. Routine uncertainty remains held and appears in a session summary. The implementation must not ask the user to rescue a missed setup or infer approval from silence.

## Review stages

1. **Evidence capture:** retain complete raw discovery, rejected/watchlist records, original source text/URLs, publication and actual event timestamps where independently established, source relationships, capture times and revision identities. Fetch only through an explicitly authorized retrieval adapter. Source instructions never acquire tool or system authority.
2. **Catalyst assessment:** separately explain freshness, materiality/tier and same underlying event across sources under the living rules. Recycled articles, syndication, stale filings, conflicting dates and insufficient source support require explicit resolution or abstention. A mover list is not catalyst verification.
3. **Setup assessment:** use the living approved entry models and actual prospective measurements. Preserve feed identity, timestamp, entitlement/coverage, levels, structural invalidation, target rationale and applicable risk inputs. Missing consolidated measurements cannot be replaced by IEX-only approximations. Do not select a target merely to pass reward/risk.
4. **Current review and confirmation:** bind review to the exact candidate/setup identity and current evidence. A prior approval, price crossing, cached snapshot or retrospective reconstruction cannot supply prospective confirmation. An invalidated or changed setup requires the existing explicit lifecycle review; uncertainty never silently resets monitoring.
5. **Deterministic decision and reconciliation:** only the existing accepted structured handoff may reach the Worker after the method is accepted. The independent Journal writer reconciles live state using its existing stable IDs and delivery barriers. Research reports never substitute for Sheet readback.

## Acceptance evidence

- Assemble an isolated, explicitly labelled evaluation set covering supported, failed, conflicting and unresolved cases. Include old-news republication, unrelated same-symbol filings, syndicated duplicates, incomplete macro calendars, stale/wrong-feed measurements, missing targets, missed triggers and changed context. Preserve disagreements and all source snapshots.
- Have an independent source-backed assessment judge the actual claims, not just JSON validity or citation existence. Avoid circular agreement obtained from the same model/prompt twice. Record the assessor and any independence limitations.
- Evaluate catalyst, setup and confirmation separately. Report disagreements, unsupported positives, abstentions and data-coverage failures with denominators. Do not invent a passing accuracy percentage or allow profitable outcomes to excuse rule violations.
- Historical fixtures establish infrastructure behavior and review agreement only. They create no retrospective entries, fills, Strategy #1 opportunities or executed-trade sample observations.
- Any proposed numerical definition, freshness duration or changed observation eligibility requires the governing master's appropriate version control. A model may not invent those policies. Operational review can remain unresolved when current rules do not support a reproducible conclusion.

## Concrete decisions before activation

The living Automation Specification must record the accepted method, evidence contract, reviewer attribution, abstention/disagreement treatment and independent validation. Strategy/Experiment changes are needed only if the proposed behavior actually changes their methodology; this proposal does not authorize such changes.

Select and verify the actual reviewer/provider, authenticated source access, current market-data measurements, hosted identities, credential renewal, artifact retention and recurring cost. Specify its available tools and least-privilege boundary. No such provider or budget is selected by this package.

Prove unattended recovery and reporting in isolated acceptance: failures retain durable evidence, ambiguous Journal delivery remains blocked, duplicate runs/reports do not generate repeated incidents, and silence never permits a trade. Then prepare exact deployment configuration and a declared prospective assessment window for review. Broker execution stays disabled throughout Phase 1.
